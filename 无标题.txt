



### 一、 技术选型与架构设计

1.  **基础框架**：**FastAPI** (Python)。它天生支持异步，且基于 Pydantic 的数据验证能完美契合您需求文档中第 6、7 节的输入输出数据结构定义。
2.  **异步任务队列**：推荐使用 **Celery + Redis**。因为是异步接口，前端提交任务后后端需要后台执行，Celery 是 Python 处理后台任务和重试机制（特别是应对百度地图 API 限流）的工业级标准。
3.  **核心算法库**：**Google OR-Tools** (`ortools.constraint_solver.pywrapcp`)。
4.  **HTTP 请求库**：`httpx` 或 `aiohttp`（用于异步并发请求百度地图 API，提高构建矩阵的速度）。

### 二、 核心难点与解决思路

#### 1. OR-Tools 建模技巧：开放起点与固定终点
OR-Tools 默认解决的是“闭环”问题（即车辆从车场出发，最后必须回到车场）。为了实现“**任意起点出发，到达企业终点结束**”的需求，我们需要在算法层面引入一个**虚拟节点（Dummy Node）**：
*   **虚拟起点**：构建一个虚拟节点 `0`。
*   **前往任意上车点**：虚拟节点到所有上车点（Pickup）的成本设为 `0`，这意味着算法可以无代价地选择任意一个上车点作为真实的第一站。
*   **到达终点并闭环**：所有上车点到“企业终点”的成本为真实成本。而“企业终点”回到“虚拟节点 `0`”的成本设为 `0`。
*   **结果解析**：OR-Tools 算出的路径会是 `虚拟节点 -> 上车点 C -> 上车点 A -> 上车点 B -> 企业终点 -> 虚拟节点`。我们只需把头尾的虚拟节点去掉，就是最终的推荐路线。

#### 2. 百度地图 API 限流与分批策略
*   由于没有企业级 AK，免费/个人开发者 AK 有严格的 QPS（每秒请求数）和并发限制。
*   **策略**：我们将 N 个点位的矩阵拆分成多个小批次（例如 5x5 或 10x10 的子矩阵），使用带有指数退避（Exponential Backoff）的重试机制来请求。如果某一批次彻底失败，则触发您的规则：“直接抛出构建矩阵失败异常”。

#### 3. 剔除不可达站点
*   在构建成本矩阵时，如果发现某个点位到其他所有点位或终点的耗时/距离为极大值（或百度地图明确返回无法规划路线），在将矩阵喂给 OR-Tools 之前，直接将该点从矩阵中剔除，并将其 ID 记录到 `unreachable_points` 列表中。

### 三、 接口交互流程 (异步模式)

1.  **创建任务接口** `POST /api/v1/route/plan`
    *   **输入**：需求文档第 6 节的 JSON 数据。
    *   **输出**：返回 `{"task_id": "uuid-xxxx", "status": "processing"}`。
2.  **查询结果接口** `GET /api/v1/route/result/{task_id}`
    *   **输出**：如果未完成，返回 `processing`；如果完成，返回需求文档第 7 节的完整输出数据（包含 `route_order`, `segments`, `unreachable_points` 等）。

### 四、 分阶段开发计划

为了保证项目稳步推进，我建议我们将后端开发分为以下四个阶段进行：

*   **阶段一：基础框架与数据模型搭建**
    *   初始化 FastAPI 项目结构。
    *   根据需求文档编写 Pydantic 模型，严格校验输入参数（经纬度格式、必填项等）。
    *   搭建 Celery + Redis 异步任务骨架。
*   **阶段二：百度地图 API 接入与矩阵构建**
    *   封装百度地图“批量算路（Route Matrix）”或“驾车路线规划”API。
    *   实现分批请求、QPS 控制和失败重试逻辑。
    *   实现不可达点位的检测与剔除逻辑。
    *   根据公式 `Cost = a * time + b * distance` 生成最终的二维成本矩阵。
*   **阶段三：OR-Tools 路径优化求解器**
    *   实现上述的“虚拟节点”建模逻辑。
    *   将二维成本矩阵输入 OR-Tools 求解器。
    *   设置求解时间限制（`max_solve_time`）。
    *   解析 OR-Tools 的输出结果，映射回真实的站点 ID。
*   **阶段四：结果组装与完善**
    *   根据 OR-Tools 排出的顺序，再次调用百度地图 API 获取具体的导航轨迹（Polyline）和分段距离/耗时。
    *   组装最终的 JSON 响应，处理异常状态（如无解、AK 无效等）。
